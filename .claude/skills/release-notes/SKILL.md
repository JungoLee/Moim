# 릴리즈 노트 (업데이트 내역)

- **단일 출처 = `frontend/src/release/releases.ts`** (배열 맨 앞이 최신). DB 가 아니라 소스에 두는 이유는 **배포 산출물과 버전이 함께 고정**돼야 "지금 보는 화면의 릴리즈 노트" 가 맞기 때문이다. 정적 export 라 더욱 — 빌드 결과물에 같이 실려야 한다.
- 노출 위치: 계정 드로어 하단(약관·개인정보 처리방침과 같은 자리) → `ReleaseModal`.
- **배포 직전에 갱신한다.** 지난 릴리즈 이후 커밋을 훑어 **사용자가 체감하는 변화만** 옮긴다.
- 쓰는 법(사용자가 읽는 글이다 — 개발 로그가 아니다):
  - 내부 용어·파일명·함수명 금지. "AvailabilityCalendar 리렌더 최적화"(X) → "빈 시간 찾기가 빨라졌어요"(O)
  - 리팩토링·문서 정리·내부 구조 변경은 **넣지 않는다**
  - 한 항목은 한 줄, `kind` 는 `feature`·`improve`·`fix`. 날짜는 `YYYY-MM-DD`

- **버전 표기** — 릴리즈마다 `major.minor.patch`. 그 릴리즈에서 **가장 큰 변화 기준으로 한 칸만** 올리고 아래 자리는 0 으로 되돌린다.
  - `major` 전면 개편·디자인 변경 · `minor` 기능 추가 · `patch` 버그 수정·다듬기
  - 목록에는 버전이 맨 앞에, 상세에는 상단에 크게 나온다.
